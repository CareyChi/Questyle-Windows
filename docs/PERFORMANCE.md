# 性能优化

记录界面动画的性能思路、已做优化和仍可改进的地方。更新流程本身见[开发文档](DEVELOPMENT.md#版本检查与-ci-发布约定)，验证结果见[验证记录](VERIFICATION.md)。

## 成本模型

主窗口和阴影窗口都设置了 `AllowsTransparency`，是 Windows 分层窗口。WPF 每画完一帧，都要把整个窗口的像素从显卡读回内存，再调用 `UpdateLayeredWindow` 交给系统合成。因此每帧的成本由三部分组成：

1. **布局**：改动 Width、Height、Margin 等布局属性会触发测量和排列，改动 Opacity、RenderTransform、Clip 只需要重绘。
2. **绘制**：文字、几何和效果（尤其是模糊）的重新绘制。半透明元素还要先画到临时表面再叠加。
3. **回读**：成本与窗口像素面积成正比，两个分层窗口各回读一次。普通动画通常只有前两项，分层窗口额外多出这一项，而且无法避免。

所以优化原则是：
- 动画只改不影响布局的属性；
- 内容不变的元素不要每帧重画；
- 尽量缩小需要回读的窗口面积。

## 已做优化

### 窗口阴影：预渲染边角拼接

原来的实现会逐帧改阴影边框的 Margin，有四项开销：
- 每帧一次布局；
- 32 DIP 的 DropShadowEffect 整面重新模糊；
- 外层 BitmapCache 因内容变化每帧重建，反而多一次绘制；
- 挖空中心用的 CombinedGeometry 每帧重新计算。

现在由 `ShadowFrame` 绘制：
- **预渲染**：在当前 DPI 下，把内框 130 DIP 的圆角矩形阴影渲染成一张位图，只在 DPI 改变时重做。
- **切片**：沿边方向，距角超过「圆角 24 + 模糊 32」后阴影是均匀的。所以每个角取 28 + 64 = 92 DIP，原样绘制；四条边取中间一列或一行像素拉伸。中心不画。
- **逐帧**：动画只改依赖属性 `Bounds`，并且它只标记重绘（AffectsRender）。每帧只做 8 次 DrawImage，坐标取整到设备像素，并关闭边缘抗锯齿，避免拼缝。
- **一致性**：静态阴影也走同一路径，所以动画开始和结束时不会出现两种画法切换造成的跳变。UI 检查把 400×300 的拼接结果与原模糊阴影逐像素比较，alpha 差不超过 2。

### 界面元素：过渡期间临时位图缓存

收缩和展开时，十余个界面块要错开淡入淡出并缩放到 0.97。不加缓存时，每个块每帧都要重画全部文字和图形，再按透明度叠加。

现在过渡期间给这些块设置 `BitmapCache(RenderAtScale = 当前 DPI 缩放)`：
- 透明度和变换的变化不会让缓存失效，每帧只是合成已有位图。
- RenderAtScale 设为当前 DPI 缩放，避免高 DPI 下缓存只有 96 DPI 分辨率而发糊。
- 开启了 SnapsToDevicePixels。
- 收起时先设置缓存，等一帧静止画面把缓存建好，再开始动画，所以第一帧动画不会因为建缓存而变慢。
- 展开结束后移除缓存，恢复正常绘制。

### 保持不变的约束

- **时钟同步**：所有过渡动画都用 `StyleTransitions.Start`，并以 `SeekAlignedToLastTick` 对齐到同一帧起点。窗口裁剪和阴影的 Bounds 用同一缓动、同一时长。
- **不改布局**：过渡只改 Opacity、RenderTransform、Clip 和阴影 Bounds，不改布局属性。
- **像素一致**：更新卡片三行在静止后释放动画时钟，以静态值绘制，与新进程画出的卡片逐像素一致。

## 验证现状

只做了离屏检查：阴影拼接与原阴影一致、Release 编译和无窗口 UI 检查。按项目约束没有显示窗口，所以没有实测帧率或帧时间，实际观感以用户在本机运行「模拟更新流程」为准。

## 进一步优化空间

按预期收益排序：

1. **卡片阶段缩小两个 HWND**
   - 收缩结束后，可见区域已经是 380×160 的卡片，但主窗口和阴影窗口仍保持全尺寸，下载和安装期间每帧仍回读整窗。
   - 做法：此时用一次 SetWindowPos，把主窗口缩到卡片大小、阴影窗口缩到卡片加 28 DIP 边距。裁剪外本来就透明，所以画面不变。
   - 展开前再恢复全尺寸，新进程也可以直接以卡片尺寸启动。
   - 难点：缩放 HWND 时 WPF 会重新布局，要确保卡片以整像素保持原位。
2. **进度条改为只重绘的动画**
   - 现在每 50 ms 对填充条的 Width 启动一次 120 ms 动画，Width 每帧都会触发布局，蓝色光晕的 DropShadowEffect 也随宽度重新模糊。
   - 可以改为固定宽度加 ScaleTransform.ScaleX；光晕用预渲染位图，或单独做一个不随宽度变化的元素。
   - 注意：缩放会拉伸两端圆角，需要把端点和中段分开绘制。
3. **交接时的阴影重叠**
   - 新进程画好卡片和阴影后，要等 4 帧才通知旧进程隐藏。这几帧里两个阴影叠在一起，卡片周围会略深。
   - 可选做法：新进程先不显示阴影；旧进程收到就绪信号后只隐藏主窗口、保留阴影，并回发第二个信号；新进程再显示阴影，旧进程随即隐藏阴影。
   - 跨进程无法保证同一帧完成，最多剩下约 1 帧的重叠或缺失。
4. **展开时的缓存建立**
   - 新进程里界面块从透明开始，各块的缓存在各自第一帧可见时才建立，会有错开的小尖峰。
   - 可以在展开前用接近 0 的透明度先渲染一帧来预热。只有实测到尖峰时才值得做。
5. **帧时间记录（开发用）**
   - 可在开发者选项里加一个开关：过渡期间记录 `CompositionTarget.Rendering` 的间隔，统计平均、95 分位和最长帧，写入日志。
   - 这样可以在用户机器上量化，而不是凭观感判断。它不在界面上显示说明。
6. **不使用分层窗口**
   - 改用 Win11 的 DWM 圆角和系统阴影，可以彻底去掉回读。
   - 但 Windows 10 没有系统圆角，裁剪收缩也只能改为逐帧调整 HWND 尺寸，而 WPF 逐帧改窗口尺寸本身就容易抖动。
   - 改动面大，目前不建议做。
