## 首次 GitHub CI 修正（2026-10-29）

推送后的 CI 依次暴露了 4 个问题，全部修正后重新推送：

1. **PEQ 暂停曲线检查**：离屏渲染按固定 1240×800 排版，窗口随后又按 runner 的工作区重新排版，导致前后采样宽度不同。现改为等布局稳定、重新绘制后再采样。
2. **过渡完成检查**：固定等待后，可能读到上一帧的动画值。等待工具改为等待结束后再等一帧渲染，避免 100 ms 动画在 115 ms 时因帧间隔而未结束的偶发失败。
3. **通道切换检查**：CI 构建带每日构建号，原测试错误地假定当前程序是正式版。现改为按被测程序自身所属通道选择要切换的目标通道。
4. **原生 PEQ 配置写入**：在本机复现到，音频引擎打开 peq.bin 时用 MoveFileEx 替换会返回拒绝访问（错误 5）。这是真实的竞态，应用写入实时 PEQ 配置时同样可能失败。应用和原生测试都改为 POSIX 语义重命名；本机确认它在文件被打开时能替换，原句柄仍读旧内容。

新增检查覆盖：读取者打开文件时 C# 与原生写入都能成功。本机最终运行：UI 376 项、原生 PEQ 27 项、协议 28 项均通过（正式版构建）；修改写入方式前，带每日构建号构建的 UI 375 项也已通过。

5. **发布脚本**：发布前按标签读取草稿返回 404，因为草稿还没有 Git 标签。现改为在发布列表中按草稿和目标标签查找。用 Windows PowerShell 模拟单页和多页 `--slurp` 输出，确认都能找到草稿；失败运行留下的草稿已删除。

## 模拟更新未切换进程的原因（2026-10-29）

- **现象**：用户运行「模拟更新流程」后，dist 中的原进程（5:45:43 启动）仍在运行。`data/temp/update` 留下了 package.zip 和已解压的 runtime、language，`previous` 为空，handoff.json 未生成，说明替换文件这一步失败后已回滚，新进程没有启动，窗口随后展开回原界面。
- **定位**：用只读方式以 DELETE 权限逐个打开运行中程序目录的 298 项，只有 `runtime/assets/dongle.png` 和 `Questyle.ico` 返回共享冲突（错误 32）。这两个文件由 WPF 图片按默认方式加载，文件一直打开，导致无法移动 runtime 目录。
- **修复**：窗口图标、设备图和编码 Logo 改为加载时一次读入内存（OnLoad）。新增检查：窗口渲染后 assets 下的文件都能以 DELETE 权限打开。临时恢复旧加载方式时，该检查准确报告这两个文件；修复后通过。
- **结果**：Release 编译 0 警告、0 错误，无窗口 UI 检查 370 项通过。build.ps1 -SkipTests 已重新打包，发布包无窗口启动检查通过。修复后的完整交接仍需用户在本机运行确认。新增[性能优化](PERFORMANCE.md)文档。
